# 可研报告 AI 智写系统 — 产品需求文档（PRD）

> 用途：发给 Coze / 开发助手，用于**初始化项目骨架与实现范围**。  
> 版本：v0.2（MVP）  
> 日期：2026-09-09  
> 变更：报告基本信息字段对标小泓星表单并裁剪（必填 / 选填 / 后置） 
> 定位：工程咨询「可行性研究报告」初稿辅助生成（对标类产品能力，独立自研，不爬取竞品）

---

## 1. 一句话目标

做一个 **PC Web 向导式 SaaS**：用户填写项目信息与财务假设 → 系统按国家发改委 2023 可研大纲分章生成报告 → 在线改稿 → 导出 **Word（含表格）+ Excel 报表**。

**不是**通用聊天机器人；**数字靠测算引擎，政策/标准靠依据库勾选，正文靠大模型按章撰写。**

---

## 2. 背景与原则

### 2.1 权威大纲

政府投资项目默认使用：

- 文件：发改投资规〔2023〕304号  
- 《政府投资项目可行性研究报告编写通用大纲（2023年版）》

企业投资可用《参考大纲》作为后续扩展；**MVP 先做政府投资通用大纲。**

### 2.2 数据分工（硬性约束）

| 类型 | 来源 | 禁止事项 |
|------|------|----------|
| 项目事实与假设 | 用户表单 / 上传 | 模型不得编造批复文号、规模、投资 |
| 财务数字 | **二期**：确定性测算引擎；**一期**：不测算，章节标【待补充】 | 一期模型不得自行编造 IRR/NPV 等 |
| 编制依据条目 | 依据包匹配 + 用户确认 | 模型不得凭空新增带文号/标准号的文件 |
| 章节叙述文字 | 大模型（输入仅限上述已有数据） | 缺数据写「【待补充】」 |
| 外部政策/标准 | 知识库元数据（标题+文号/标准号+链接） | MVP **不存原文**，只存可核对信息与链接 |

### 2.3 合规声明（产品文案必有）

成果为 **AI 辅助初稿**，正式报审须人工复核；系统不替代咨询资质与签字责任。

## 3. MVP 范围

### 3.1 In Scope（第一期：只做智写）

1. 项目 CRUD 与状态流转（登录可占位）  
2. 向导：基础信息 → 编制依据 → 大纲确认 → 分章生成 → 改稿 → 导出 Word  
3. 内置大纲：`gov_feasibility_2023`  
4. 编制依据：依据包自动推荐 + 勾选确认（可补本项目批复类文件）  
5. 分章调用大模型生成正文（财务章无测算数字时写【待补充】）  
6. 导出 `.docx`（表格可先空或占位）  
7. 配置：大纲 JSON、章节提示词；依据库由白名单官网自动同步  

### 3.2 Out of Scope（第一期不做 / 二期再做）

- **财务测算引擎、智算、Excel 报表导出**（二期）  
- 全网无边界爬虫（仅允许白名单官方栏目元数据同步）  
- 依据库人工条目录入后台  
- 手机端完整编辑  
- 计费中台  
- 多行业全覆盖、企业投资大纲、节能报告等

## 4. 用户角色

| 角色 | 能力 |
|------|------|
| 咨询编制人员 | 建项目、填表、确认依据、生成、改稿、导出 |
| 管理员/运营 | 触发/配置白名单同步源、大纲与提示词；**不**做依据条目录入 |

---

## 5. 核心用户流程

```
登录 → 项目列表 → 新建可研
  → ① 基础信息
  → ② 编制依据（系统推荐 → 用户确认）
  → ③ 财务测算（计算并保存）
  → ④ 大纲勾选与字数设置 → 开始生成
  → ⑤ 报告工作台分章查看/编辑/单章重写
  → ⑥ 导出 Word + Excel
```

状态建议：`草稿` → `信息已填` → `测算完成` → `生成中` → `已生成` → `已导出`

## 6. 大纲结构（gov_feasibility_2023）

生成必须按下列一级/二级标题树（可配置 optional 显隐）：

1. **概述**  
   1.1 项目概况  
   1.2 项目单位概况  
   1.3 编制依据（实务可再拆 1.3.1 规划政策 / 1.3.2 标准规范）  
   1.4 主要结论和建议（建议最后生成）  

2. **项目建设背景和必要性**  
   2.1 项目建设背景  
   2.2 规划政策符合性  
   2.3 项目建设必要性  

3. **项目需求分析与产出方案**  
   3.1 需求分析  
   3.2 建设内容和规模  
   3.3 项目产出方案  

4. **项目选址与要素保障**  
   4.1 项目选址或选线  
   4.2 项目建设条件  
   4.3 要素保障分析  

5. **项目建设方案**  
   5.1 技术方案  
   5.2 设备方案  
   5.3 工程方案  
   5.4 用地用海征收补偿（安置）方案（optional）  
   5.5 数字化方案（optional）  
   5.6 建设管理方案  

6. **项目运营方案**  
   6.1 运营模式选择  
   6.2 运营组织方案  
   6.3 安全保障方案  
   6.4 绩效管理方案  

7. **项目投融资与财务方案**（数字来自测算引擎；可插表）  
   7.1 投资估算  
   7.2 盈利能力分析  
   7.3 融资方案  
   7.4 债务清偿能力分析（optional）  
   7.5 财务可持续性分析（optional）  

8. **项目影响效果分析**  
   8.1～8.5 经济/社会/生态环境/资源能源/碳达峰碳中和（后者 optional）  

9. **项目风险管控方案**  
   9.1 风险识别与评价  
   9.2 风险管控方案  
   9.3 风险应急预案  

10. **研究结论及建议**  
    10.1 主要研究结论（建议最后生成）  
    10.2 问题与建议  

11. **附表、附图和附件**（不做 LLM 正文；导出时挂 Excel/附件清单即可）

## 7. 页面与信息结构（初始化前端/Bot 流程按此拆）

### 7.1 项目列表

- 展示：名称、行业、地区、状态、更新时间  
- 操作：新建、进入、删除、继续未完成步骤  

### 7.2 新建项目（最少必填）

创建项目时先收最少量字段，其余进「报告基本信息」页：

- 项目名称*  
- 投资性质*：政府投资（MVP 固定或仅此选项）  
- 大纲：`gov_feasibility_2023`（简化版后期做）  

也可与 7.3 合并为一页；实现时二选一即可。

### 7.3 报告基本信息（对标小泓星结构，按 MVP 裁剪）

> 原则：必填保证能生成初稿与匹配依据包；长文本/上传可选；缺项可标【待补充】继续。  
> 「编制依据」不在本页填写，仍走单独步骤。财务详细数字走测算页。

#### 1. 基本信息

| 字段 | MVP | 说明 |
|------|-----|------|
| 投资及财务分析 | 一期固定关闭 | 固定「不做财务分析」；二期再开放选择 |
| 项目名称 | 必填 | ≤100 字，完整项目名 |
| 项目行业 | 必填 | 枚举（建筑、市政公用、农林、生态环境…）；用于匹配依据包 |
| 细分领域 | 必填 | 自由文本 ≤50，如「市政道路」「小学」；工程类型标签也可用此字段 |
| 项目性质 | 必填 | 新建 / 改建 / 扩建 / 改扩建 |
| 项目单位名称 | 必填 | ≤100 |
| 项目单位概况 | 选填 | 长文本 ≤2000 |
| 项目地点 | 必填 | 省市区选择 + 详细建设地点（≤100） |
| 项目建设期 | 必填 | 带单位文本，如「1.5年」「24个月」 |

#### 2. 市场需求与产出规模

| 字段 | MVP | 说明 |
|------|-----|------|
| 建设内容和规模 | 必填 | 长文本 ≤3000；直接用于第 1 章「建设内容与规模」 |
| 主要产品/服务 | 必填 | 长文本 ≤3000 |
| 目标市场 | 必填 | ≤100 |
| 市场数据/市场分析报告 | 选填 | 文本 ≤3000 + 可选上传 Word/PDF（≤20M） |

#### 3. 项目前期准备

| 字段 | MVP | 说明 |
|------|-----|------|
| 前期工作进展 | 选填 | 长文本 ≤2000 |
| 是否涉及土地征收 | 必填 | 是 / 否；控制大纲「用地征收补偿」等章节显隐 |

#### 4. 工程技术方案（MVP 精简）

| 字段 | MVP | 说明 |
|------|-----|------|
| 建设方案编制模式 | 选填（二期） | 专家模式 / 精简模式；首版可固定为精简 |
| 技术经济指标 | 选填 | 文本 ≤3000 + 可选上传 |
| 技术方案 | 选填 | 文本 ≤3000 + 可选上传 |
| 设备清单 | 选填 | 文本 ≤3000 + 可选上传 |
| 设计方案文本 | 选填 | 文本 ≤3000 + 可选上传 |

#### 5. 投资与运营

| 字段 | MVP | 说明 |
|------|-----|------|
| 项目能源消耗量 | 后置 | 不做节能专篇时可隐藏 |
| 项目资金来源 | 必填 | 多选：自筹 / 银行借款 / 政府专项债 / 中央预算内 / 财政资金 / 超长期国债 / 政府补贴 / 政府性基金 / 公司债 / 融资租赁 / 企业债 / 其他 |
| 建设管理模式 | 必填 | 工程总承包 / 全过程工程咨询 / 代建管理 / 其他 |
| 项目运营模式 | 必填 | 自主运营 / 委托第三方 / 其他 |

**本页操作**：保存草稿；校验通过后进入「编制依据」（或若合并流程则「生成大纲」前先过依据确认）。

**校验规则**：标 * 的缺一不可进入下一步；选填为空时章节生成写【待补充】，不拦初稿。

### 7.4 编制依据页（关键）

- 系统根据规则展示候选列表，分组：  
  - `policy`：主要规划及产业政策  
  - `standard`：主要标准规范  
  - `project`：本项目批复/委托（用户添加）  
- 操作：勾选/取消、手填（类型*、名称*、文号/标准号、发文单位、日期、可选链接）、上传（可选，只存文件 URL）  
- **生成报告前必须有一次确认（确认后锁定快照）**  

### 7.5 财务测算（简化档）

**输入（白格）示例**  
建设投资分项或总投资、资本金比例、贷款利率与期限（可选）、建设期、收入/成本关键假设（可极简）  

**输出（灰格/结果）**  
总投资、建设投资、建设期利息（可简化）、流动资金（可简化）、资本金/债务、基础盈利指标（有则算，规则写清）  

提供「重新计算」「保存」「下一步」；允许「跳过测算」但需确认（文本弱化财务章）

### 7.6 大纲与生成

- 树形勾选章节（optional 可关）  
- 目标字数（如 3万/8万/自定义）  
- 按钮：开始生成  
- 展示分章进度  

### 7.7 报告工作台

- 左：章节目录 + 状态  
- 中：正文编辑（可改）  
- 右：本章所用项目字段 / 测算字段 / 依据引用（可先简陋）  
- 操作：保存本章、重新生成本章、导出  

### 7.8 导出

- `报告.docx`：标题样式 + 正文 + 财务相关表（Word 表，数值来自测算）  
- `报表.xlsx`：测算明细  
- 记录生成时间、大纲版本  

### 7.9 管理配置（可用表格/后台）

- 依据库白名单同步源（URL → 包），条目由 `pnpm basis:sync` 自动入库  
- 大纲 JSON  
- 章节提示词模板  
- 财务参数版本号

## 8. 编制依据：如何自动选择（给算法/规则引擎）

### 8.1 不存原文 + 自动同步

每条依据存：`title`、`doc_code`（文号或标准号）、`issuer`、`category`、`region`、`industry_tags`、`eng_type_tags`、`status`（现行/废止）、`source_url`、`checked_at`  

入库方式（**禁止人工逐条录入后台**）：  
- 配置按**来源网站**分组的白名单官方 **原文详情 URL**（中国政府网 / 发改委 / 住建部 / 标准公开系统等）  
- 定时或手动执行同步任务：抓取页面**元数据**（标题、文号、来源站、原文链接），写入全局共享 `basis_packs`  
- 每条依据必须保留可点开的原文链接；不抓取、不存储政策/标准全文；模型不得凭空新增带文号的文件  

链接可失效；**主键是文号/标准号**，链接可后续由同步任务修补。

### 8.2 依据包（Pack）

MVP 至少配置：

| pack_id | 触发条件 |
|---------|----------|
| `pack_common_gov` | 所有政府投资项目 |
| `pack_finance_eval` | 启用财务分析时 |
| `pack_eng_municipal_road` | 工程类型=市政道路 |
| `pack_region_{省}` | 按省份，如河南 |
| `pack_industry_{行业}` | 按行业标签，如林草防灭火（示例包） |

**选择伪代码：**

```
selected = pack_common_gov
if finance_enabled: selected += pack_finance_eval
if eng_type == 市政道路: selected += pack_eng_municipal_road
if province: selected += pack_region_{province}
if industry_tags: selected += 对应行业包
selected += 用户上传/手填的本项目文件
去重，过滤 status!=现行
写入 project_basis_snapshot（用户确认后）
```

生成 1.3 时：**只渲染 snapshot**，可用程序拼列表，无需 LLM 选题。

### 8.3 报告中的呈现格式

```
1.3 编制依据
1.3.1 主要规划及产业政策
1. 《标题》（文号）
...
1.3.2 主要标准规范
1. 《标题》（标准号）
...
```

## 9. 分章生成（LLM）要求

### 9.1 输入上下文（每章）

- 本章标题与写作要点（来自大纲配置）  
- 项目基础信息 JSON  
- 测算结果 JSON（财务章必带）  
- 已确认编制依据列表（政策符合性、编制依据章必带）  
- 明确指令：禁止编造文号/数据；缺则【待补充】  

### 9.2 生成顺序

1. 先并行或顺序生成 2～9 章中非总结章  
2. `1.4`、`10.1` 最后生成（依赖全文摘要与财务结论）  
3. `1.3` 优先程序渲染列表，或 LLM 仅做标题包装  

### 9.3 重试与编辑

- 支持单章重写  
- 用户手工编辑不强制再走模型

## 14. 验收标准（MVP Done）

1. 能新建「河南 + 市政道路」示例项目并走通全流程  
2. 编制依据页能自动勾选通用包+工程包+财政评包，用户可改，确认后写入 1.3  
3. 财务简化测算有结果，且第七章/Word 表数字与测算一致  
4. 至少完整生成大纲中所有非 optional 章（optional 可默认关）  
5. 导出 docx 含标题层级与至少 1 张表；导出 xlsx 含测算数据  
6. 任意章缺关键数据时出现【待补充】，且不出现明显虚构文号（抽检）
